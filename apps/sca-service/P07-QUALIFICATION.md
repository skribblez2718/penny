# P07 offline VM qualification (opt-in)

`runP07Qualification` in `src/p07-vm-runtime.ts` is a standalone operator-invoked harness. It is **not** registered with the SCA broker and does not authorize `application_test`. A passing fixture is not evidence of production containment.

Supply `config` and `plan` as externally managed values. No image, executable, operator path, or secret is stored in this repository. The live test reads a JSON object `{ "config": ..., "plan": ... }` from the absolute file named by `PENNY_P07_VM_LIVE_CONFIG`. This environment variable is the explicit opt-in for a real boot; the ordinary suite skips the live test. Set it only on an authorized KVM host with a reviewed, offline, cloud-init-capable Ubuntu Jammy qcow2 and a benign plan. The test does not independently establish that the image is Jammy or that its provenance is trusted.

- `config.qemu`, `config.qemu_img`, `config.iso_builder`, `config.base`: each has `path` (absolute, canonical, symlink-free) and `sha256` (exact file bytes). The three tools must be ELF executables. The base must be a single-link, owner-owned, non-writable qcow2 without a backing file. The workspace parent must already exist, be owned by the calling non-root identity, and be inaccessible to other users (mode 0700). Tool files must not be group/world writable. The runtime also requires accessible `/dev/kvm`.
- `expected_qemu_version`, `expected_qemu_img_version`, `expected_iso_version`: exact trimmed combined output of each tool's `--version`. The ISO builder must accept `-quiet -output <file> -volid cidata -joliet -rock user-data meta-data` (genisoimage-compatible). `base_virtual_bytes` must match `qemu-img info --output=json`; the base must have no backing file.
- `limits`: `startup_ms` (also bounds each setup command and time until the guest's first marker), `runtime_ms` (absolute QEMU lifetime), `output_bytes` (serial and stderr combined), `overlay_bytes` (observed file size and allocated blocks), `result_items`, `termination_ms`. The runtime enforces schema ranges before launching. The fixed VM profile uses one vCPU, 1024 MiB RAM, a qcow2 overlay, a read-only NoCloud ISO, KVM, QEMU sandbox, no NIC, no monitor, no host share, and no guest agent.
- `plan`: `{ "plan_sha256": ..., "policy_sha256": ..., "input_sha256": ..., "script": ... }`. Compute `plan_sha256` as SHA-256 of the repository's canonical JSON of `{ policy_sha256, input_sha256, script }`. The script is bounded guest data written to the NoCloud seed; it executes **only within the guest**. A benign script may write a JSON array of strings to `/var/lib/penny/items.json`. If it does not, the runner emits an empty array. The host accepts only one canonical marker-delimited JSON result matching all five expected digests and the result-item ceiling. These are guest-reported bindings, not cryptographic guest attestation; observations remain untrusted. Guest text is never evaluated by the host.

**Disposition:** success is returned only after observed process-group disappearance, validated guest result, and verified workspace removal. A `P07VmError` with `termination_uncertain` or `cleanup_uncertain` includes the retained workspace path for manual quarantine/inspection; do not automatically retry, delete, or reuse it. Other failure codes indicate failed qualification with confirmed cleanup. Preserve external execution records before relying on an outcome: this standalone harness has no durable job journal.

**Remaining qualification work before any production use:** repeat on the deployed host with an independent network-denial boundary, a dedicated low-privilege account, cgroup resource controls and a kernel-enforced workspace/overlay quota. The current 50 ms overlay observation is not a hard quota; QEMU could grow a file between samples. Hashing a path immediately before use does not atomically bind an `execve` or QEMU's later open against a privileged concurrent mutator. A service crash is not covered by the in-process deadline or process-group proof. The live test checks boot and a benign result, not VM escape resistance, offline dependency completeness, policy authorization, durable quarantine, or artifact custody. Leave the broker adapter null until separate production admission and crash recovery are implemented and independently reviewed.
