# P02 controlled-host scanner and inventory candidate — live boundary trial, inactive

The candidate remains **unregistered and inactive pending formal qualification**. Authorized host-boundary trials have now run the exact controlled worker under systemd and bwrap for every selected Semgrep rule (four PHP and five JavaScript/TypeScript), Gitleaks, and the native Tree-sitter inventory bundle. Those trials also exercised a containment canary, cancellation before launch, in-flight cancellation, the systemd runtime limit, and proven cleanup. This establishes only that the exercised boundary paths worked on that measured host. It is not a predecessor-bound P02 campaign, host attestation, formal qualification record, or activation authority.

The host uses a two-phase policy gate: after all request, input, read-only, forbidden-path, identity, namespace and network checks, the worker creates a 0600 `/p02/control/ready` marker containing exactly the canonical request SHA-256 and a newline. It waits for a 0600 `/p02/control/go` containing exactly `ok` and a newline; missing go is bounded by the requested runtime and cannot dispatch a child canary, inventory import or scanner. The parent must observe the running unit with its full effective policy, verify ready through a no-follow descriptor (regular file, sole link, owner, mode, length and bytes), re-read the running policy, and only then create go exclusively. A failed go write is treated as a possible release, never a safe retry. Cancellation and the systemd runtime limit still fence the unit. The worker removes both gate files before writing the final receipt; the parent accepts only `probe` and `receipt.json` (plus `inventory.json` for inventory) in the control bind and verifies the exact probe bytes, and never accepts an exited result unless the gate was opened.

Inventory has its **own closed controlled-host parser path**, not scanner qualification: census and dependency extraction remain bounded host-side transformations, while live-qualified inventory requires a factory-issued runner for the admitted custody, operation, profile and deployment. A separate fixed worker bundle and exact Tree-sitter native package closure are mounted read-only; the bundle reads only the canonical admitted input, and the parent verifies the bounded canonical result and source/tool bindings without rebuilding with the native parser. The issued runner exposes a deep-frozen, bounded containment-evidence entry only after the host run, result validation, private auxiliary cleanup, and harness workspace cleanup succeed. Final P02 component authority still verifies inventory evidence, dependency/census rebuilding and component coherence; for live-qualified inventory it does not invoke the parser again. Simulated tests retain deterministic parser rebuilding. The package descriptor permits only the exact platform-specific files required by the four pinned Tree-sitter packages and `node-gyp-build`; no package installation, project-root bind or full `node_modules` bind is provided. Missing or forged runners block as `controlled_inventory_unavailable`.

A caller supplies a private absolute source root and an ordered exact manifest of regular non-symlink paths, byte lengths and SHA-256 hashes, plus a manifest digest. Limits: 256 files, 16 MiB each and 64 MiB total. The caller also supplies protected state roots, which cannot overlap the sealed runtime. The parent rejects drift, extras, links, hard links, path collisions, traversal and overlapping sensitive roots, copies the tree to fresh private staging using no-follow reads, sets staging directories to 0555/files to 0444 and verifies both trees before launch and after a receipt. Only the staged tree is mounted read-only at `/input/source`. The one-file canary uses the same protocol. For P02 custody materializations, `deriveP02HostSourceManifestV1` derives the scanner file list and digest from the validated P01 manifest and custody bytes, **not** a filesystem walk. The source generation marker is verified separately against the admitted manifest/custody digests, root inode and exact metadata; it is never copied into the sandbox source tree. The verifier rejects any other unlisted file or directory. Direct canary trees still reject all extra entries. The materialized root is 0555; the factory requires its private 0700 staging parent. Enumeration and file hashing verify the admitted list before the harness stages it and again at the harness boundary; neither grants new authority to a discovered file.

The source limits do not apply to the distinct `SealedRuntimeTreeV1` descriptor: at most 50,000 regular files, 512 MiB per file, 2 GiB total and 8 MiB for the canonical manifest. Its host root is a private same-UID sealed copy beneath a private owner-controlled parent; hashing is streamed, including the worker’s executable check. Runtime root and all entries are verified before launch and after execution. No symlinks, hard links, unlisted/empty directories, devices, path traversal or case collisions are admitted.

The profile binds the operation kind, deployment pin, fixed worker/launcher, controls, limits, a pinned Node runtime and its explicit closure, and a separate tool-runtime union: exact static executable (Gitleaks), or an ordered, fully verified sealed directory mounted read-only from its private host `tree.root` to a distinct exact sandbox `mount_root` with an explicit executable relative path (Semgrep, with the descriptor explicitly pinned to version 1.168.0). The caller must supply the **measured Semgrep 1.168.0 Python closure and exact executable hash**; the repository intentionally contains no operator runtime. The live trial supplied and verified one private measured closure, including the small read-only host closure and trust data Semgrep required, but that measurement remains trial evidence rather than a reusable public runtime. The worker executable path is `mount_root` plus the admitted relative path. A nested mount such as an exact pyenv version under a home root is permitted, but the home parent is created as an empty sandbox directory, never bound. Mounts at home roots, protected project/state paths, reserved paths, or any other destination are refused. The profile and runtime digest bind both roots and the tree manifest digest. The code never substitutes another executable or derives paths from the operator project. Sealed files/directories must be same-UID owned and not owner-writable; same UID can chmod a directory later, so pre/post verification is residual evidence, not immutable execution proof. The only writable sandbox bind is the parent-visible private `/p02/control` directory; `/scratch` is a separate capacity-bounded private tmpfs. See [the shared scratch boundary](P02-SCRATCH-TMPFS.md) for limits, privilege dropping, deployment pins and exact scope. The scanner worker uses a dedicated temporary subtree and removes it before publishing a receipt, streams file hashes without loading large executable bytes into memory, and caps each raw stream at 4 KiB and the canonical receipt at 64 KiB. It has code-defined Semgrep and Gitleaks arguments/environment; no caller argv, shell, URL, or mount destination. Its bounded raw process result is only in the private immediate receipt; the P02 Gitleaks operation still minimizes output before artifact persistence. If termination cannot be proven, private control/staging files can remain for operator recovery and **may contain raw secrets**: restrict access, quarantine and securely dispose of it. Inventory staging also holds the admitted source bytes and a parser result until proven termination and cleanup; treat uncertain inventory workspaces as private custody, not harmless diagnostics.

A live-qualified attestation and isolation evidence carry one exact six-key `operation_profiles` map (inventory, Semgrep PHP, Semgrep JS/TS, Gitleaks, OSV Composer, OSV npm). Their shared `profile_sha256` is the SHA-256 of the canonical JSON map: it binds the campaign as a whole, **not** an individual runner. Each operation request instead uses its own map entry. The host adapter re-reads the exact admitted live evidence input and checks its map and aggregate against the runtime before dispatch; a missing or cross-spliced map cannot fall back to the aggregate. Simulated-test evidence has no operation map and retains its existing single-profile behavior. Issued inventory and scanner capabilities still must match the selected operation hash and the deployment identity.

The adapter's default direct process runner remains for deterministic tests and backward compatibility. Live-qualified P02 scanners require **factory-issued** controlled runners in the operation-specific `controlled_process_runners` map (`semgrep_php`, `semgrep_js_ts`, `gitleaks`); neither a structurally matching custom runner nor a direct static-plan qualification runner qualifies. The adapter checks kind, profile, deployment, staging parent, measured executable, timeout/output budget, and **all** selected rule digests before any scanner component dispatch. Missing or mismatched capability returns blocked. Inventory has a separate issued-runner requirement; OSV remains blocked under this unqualified boundary even if scanner and inventory runners are installed. Each factory fixes the source manifest without a mutable root, a rule digest allowlist, staging parent, tool runtime (including `mount_root` for sealed Semgrep), Node closure, deployment, controls, protected roots, workspace parent and limits. It accepts only the deterministic operation source root from the process `cwd` and the rule path in the exact `--config` slot; Semgrep rule indices may vary, so all admitted JS/TS rules use one JS/TS factory. It rejects symlinked or out-of-parent paths, mutated or extra source files, unlisted rule bytes, changed arguments/environment/executable and changed resource requests before dispatch. The profile digest excludes per-job source/rule paths and nonce; each harness plan and receipt binds the actual root and rule path/hash. `deriveP02HostRuleDigestsV1` projects the admitted selected-rule bundle for an operation; the Gitleaks configuration rule ID must be provided explicitly and its digest is the sole allowlisted entry. No campaign wiring, closure measurement, registry activation or artifact minting is performed here. The scanner result still passes the existing component validators and host authority. An exact live P02 admission must separately prove the frozen source, rules, executable measurement, runtime closure, deployment, effective unit policy, scratch tmpfs capacity, egress policy, process-tree death, minimization and retention. The harness enforces `/scratch` tmpfs capacity, not a disk quota; it has no independent network audit. A worker in a private cgroup namespace sees `/`, not the host unit path; the parent independently checks the host unit properties. No active registry or campaign was changed.

Ordinary tests exercise only static and adversarial offline paths. The reusable live canary remains gated by `PENNY_P02_HOST_LIVE=1` with a caller-supplied `PENNY_P02_HOST_CONFIG`; stale single-file fixtures fail validation. The separate boundary-trial driver is operator-authorized staging, not an ordinary test or activation mechanism. Live execution requires separate authority on a disposable controlled host. Do not issue a P02 PASS from this candidate: a formal run must still bind genuine predecessor and authority references, preserve operation-level results and minimized positive Gitleaks evidence, establish an accepted scratch/quarantine policy, and receive independent formal review.
