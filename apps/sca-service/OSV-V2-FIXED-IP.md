# In-process fixed-IP OSV v2 HTTPS smoke

`createFixedIpOsvV2Transport(ips)` is an opt-in, in-process HTTPS transport for the OSV v2 request shape. It is exported but **not registered with a production broker adapter**. Its `ip_confinement` is **`not_enforced`**. A fixed socket lookup, SNI, and certificate hostname verification constrain this request's destination and identity but do not create an independent worker or firewall. The P02 executor requires `external_worker_required` and denies this transport with `ip_confinement_unmet` before making a request. Do not change the label or use a caller-supplied flag to bypass that gate. A separate inactive external-worker candidate is described in [P02-OSV-EGRESS.md](P02-OSV-EGRESS.md). It has not been live-qualified or activated; this in-process smoke remains `not_enforced`.

The caller must authorize the lookup, measure current public IP addresses for `api.osv.dev` out of band, and supply 1–8 literal addresses. The transport does not resolve DNS, use proxy environment variables, accept redirects, or read a repository manifest. Refresh stale addresses out of band; there is no DNS fallback. IP admission alone does **not** establish OSV ownership or routability. TLS must verify `api.osv.dev`.

## Public-unicast admission policy

The constructor rejects nonliteral/ambiguous addresses, duplicates, IPv4 multicast/reserved space, IPv6 outside `2000::/3`, and every relevant prefix in the [IANA IPv4 special-purpose registry](https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml) and [IANA IPv6 special-purpose registry](https://www.iana.org/assignments/iana-ipv6-special-registry/iana-ipv6-special-registry.xhtml), reviewed **2026-09-23**. It excludes special-purpose assignments **even when the registry marks them globally reachable** (for example, protocol anycast), rather than attempting exceptions within broad prefixes. Specifically, the deprecated `192.88.99.0/24` 6to4 relay block, including the non-globally-reachable `192.88.99.2/32` 6a44 address, is denied. IPv6 translated/mapped/unique-local/link-local addresses cannot pass the `2000::/3` check; `2001::/23`, `2001:db8::/32`, `2002::/16`, `2620:4f:8000::/48`, and `3fff::/20` are denied within it. See the source for all IPv4 prefixes. This pinned registry snapshot must be updated when IANA assigns new special-purpose blocks. It is not a live routing or ownership test and is not an independent egress control.

The allowed request is exact `POST https://api.osv.dev/v1/querybatch` with the planned JSON shape or advisory `GET /v1/vulns/<id>`. Port 443, SNI, and certificate hostname verification are required. Pre-response connection failures may try the next supplied address; HTTP responses, redirects, TLS identity failures, cancellation, and size/time failures are not retried. Calls bound inactivity and response bytes. Deployments still need separately attested egress controls that deny all other destinations; a passing smoke does not demonstrate such a policy.

## Live connectivity and semantic smoke (explicit opt-in)

The ordinary `apps/sca-service` test suite skips `tests/osv-v2-fixed-ip.live.test.ts`. On an authorized network, set `PENNY_OSV_V2_LIVE_CONFIG` to JSON with exactly `ips` (operator-measured current literal IPs), `package` (an approved benign npm name), and `version` (its approved version), then run `bun run test` from `apps/sca-service`. Never set this variable in routine CI or on a host without approved network access. Unset it afterward.

The test first verifies that the P02 executor **denies** this transport. It then directly sends the exact planned single-coordinate batch through the fixed-IP transport and validates HTTP status, origin/redirect behavior, batch JSON structure, result-to-coordinate binding, and advisory ID syntax using the same batch parser as the executor. It prints only the coordinate binding digest, raw response digest, status, and advisory count. It does **not** fetch advisory documents, produce an OSV v2 result/plan evidence record, satisfy `external_worker_required`, or issue live-qualified P02 evidence. A passing test establishes connectivity and batch semantics for that IP and time only.

No source corpus, lockfile, secret, or other dependencies are read or sent. The approved coordinate is sent to the fixed OSV origin; review outbound disclosure before opting in. The test does not qualify deployment egress policy, future IP freshness, or endpoint ownership beyond TLS identity on that connection.
