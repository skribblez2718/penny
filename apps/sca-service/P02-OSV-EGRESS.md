# P02 OSV object-capability candidate (live boundary trial, inactive)

The earlier service-unit IP-filter candidate is **denied historical evidence**, not a fallback. On the tested host, a transient user unit reported `IPAddressDeny=::/0 0.0.0.0/0` and the exact `IPAddressAllow=142.250.10.121/32`, yet a connection from that unit to unapproved `1.1.1.1:443` succeeded. Neither a systemd property report nor the old canary demonstrated confinement. Do not activate or qualify that candidate.

The replacement profile is `preconnected-socket-object-capability-bwrap-netns-v1`. A live P02 attestation and its isolation evidence share an exact six-operation profile map; `profile_sha256` is SHA-256 of the canonical JSON map and binds the whole campaign. It must not be passed as an OSV transport profile. The Composer and npm requests use `operation_profiles.osv_composer` and `operation_profiles.osv_npm` respectively; the adapter checks the exact evidence, runtime, request and factory-issued transport profile before any nonempty send. There is no aggregate-hash or simulated-mode fallback for a live operation. The factory issues a transport only for a complete validated OSV v2 plan. Its digest binds the request and mapping, ordered approved public literal IP set, pinned CA, Node runtime and closure, worker bytes, deployment source, control binaries, private workspace and resource limits. The caller supplies every path and pin. The in-process fixed-IP transport remains `not_enforced`, and an empty coordinate set makes no network request.

For each send the closed host checks pins and stages only the permitted files. It selects the **first** approved literal IP, connects directly to that IP on port 443 with a bounded timeout and cancellation, pauses the TCP socket before reading, and checks the kernel peer IP and port. It does not send HTTP or TLS, resolve DNS, consult a proxy, or try another IP. The parent passes that connected socket on standard input (fd 0) through `systemd-run --user --scope` (the scope command is a child of systemd-run, not spawned by a service manager) to bwrap. The shared launcher uses Node execve, which preserves only standard input/output/error; the former fd 3 path cannot survive this privilege-dropping transition. Bwrap unshares the network, user, PID, IPC, UTS and cgroup namespaces, grants only namespace-local `CAP_SYS_ADMIN` and `CAP_SETPCAP` to the fixed launcher, clears environment and exposes exact read-only staged mounts, a parent-visible `/osv/control` bind and a private capacity-bounded scratch tmpfs. The launcher remounts scratch and drops all capabilities before the worker; see [the shared scratch boundary](P02-SCRATCH-TMPFS.md) for required pins, closure and exact scope. The parent's duplicate is closed immediately after spawn.

The worker checks its inherited standard-input socket kernel peer against the bound request. It confirms the fresh network namespace exposes only loopback and has no IPv4 default route, then proves that a new connection to a separately supplied unapproved public canary is denied with `ENETUNREACH`, `EHOSTUNREACH`, `ECONNREFUSED`, `EACCES` or `EPERM`. (A fresh Linux network namespace can contain kernel-created unreachable IPv6 default entries on loopback; interface census plus the live negative connection is the operative proof.) This is an **object-capability plus network-namespace boundary, not a firewall**. The worker never opens an OSV socket or resolves OSV DNS. Only after the parent verifies the running scope and canary receipt and opens `go` does the worker wrap that socket in TLS with pinned CA, `api.osv.dev` SNI and Host, then send exactly one fixed POST or GET. Redirects, compressed or non-JSON responses, unexpected status, size overflow and mapping drift fail closed. There is no retry.

The worker writes a bounded receipt through `/osv/control` and waits for the request-bound `finish` file. The parent validates the receipt, response and mapping, observes the still-running scope a second time, then opens finish, awaits the scope command exit, verifies zero-task inactive/failed state, checks staged and original pins, kills/stops the entire scope, verifies zero tasks and removes the workspace. Failure after `go` is conservatively uncertain: it never grants a replay. Failure to establish cleanup leaves the workspace for quarantine and produces no success evidence. The parent has an independent wall-clock limit; scopes do not supply `ExecMainStatus` or `Result` as a send oracle. `NoNewPrivileges` is an execution-context setting, not an asserted scope property; the worker verifies no-new-privileges and zero capabilities directly after the launcher/setpriv transition, rather than asserting them as scope properties.

`readP02OsvTransportEvidenceV1` returns only deep-frozen completed, cleaned-up entries from a factory-issued transport. Each entry binds the ordered approved set, selected kernel peer and port, `network_namespace_denied: true`, the isolation label, canary denial and exact denial code, scope observations, receipt and response digests and byte count, timestamps, status and cleanup. It exposes no raw response, request body, coordinates, credentials, environment or workspace path. Entries appear only after cleanup and mapped result validation. This collection surface does **not** qualify the deployed host.

Authorized live boundary trials have exercised nonempty npm and Packagist queries, advisory retrieval, contemporaneous DNS selection with TTL evidence, TLS ownership verification, cancellation before scope launch, cancellation after the `go` gate, an inactivity timeout, uncertain post-send fencing, zero replay, and workspace/scope cleanup. The successful requests each recorded loopback-only fresh-network-namespace state, a denied unapproved canary, exact inherited kernel peer, status 200 and completed cleanup. These trials establish only that the exercised paths worked on the measured host; their profile name is `p02-osv-preconnected-netns-r1`. They are not a formal host attestation, predecessor-bound P02 operation, independent qualification record, or activation authority.

Offline tests still inspect grammar, forged controls, scope sequencing and evidence and remain important for branches that a public endpoint cannot deterministically induce. The reusable live test is skipped unless both `PENNY_P02_OSV_LIVE_APPROVED=1` and a caller-supplied `PENNY_P02_OSV_LIVE_FIXTURE` are set; routine checks must not set them. The build copies the worker and shared launcher byte-for-byte to `dist`; a worker or deployment change alters the profile and requires renewed qualification. Do not activate this candidate until genuine campaign references, operation-level Composer/npm integration, retention policy and independent formal review are complete.
