# Paired Skill Evaluation

## Scope

Penny's minimum evaluator freezes a held-out population and paired baseline/candidate plan before any trial, executes the complete schedule through the TypeScript orchestration path, scores with registered deterministic graders, and persists one immutable aggregate result. It measures candidates; it does not admit, promote, enable, move, or discover them.

Benchmark populations, plans, guidance, calibration packages, journals, and results are caller-local data. The repository ignores `$PROJECT_ROOT/evals/`; normal publication checks must pass without that directory. The offline synthetic known-delta population is a harness self-test when locally supplied. It is not evidence for a real candidate warrant and is exempt only from the real-population five-domain minimum.

## Closed contracts

- `EvaluationPopulationV1` binds purpose, population ID/revision, `held_out` split, contamination group, and unique tasks. Every task includes domain, trigger expectation, goal, closed constraints, exact input artifact IDs, and one grader case ID.
- `EvaluationReadinessCalibrationCohortV1` binds a distinct non-scoring `calibration` split, revision, closed tasks, and host-only oracle markers. `EvaluationReadinessCalibrationDefinitionV1` binds its digest, exact arms, exact task count, success floor, and fail-fast integrity policy.
- `PairedEvaluationPlanV1` binds the exact candidate contract digest, population digest, direct baseline definition digest, named ablation digests, repetitions, provider/model/runtime/thinking/rate card, budget policy, complete deterministic grading-definition digest, one complete `EvaluationImplementationBindingV1` digest, pair-order seed, primary metric, all thresholds, failure accounting, cost/latency ceilings, optional named-ablation non-inferiority policies, optional non-scoring readiness calibration, an optional deterministic mutation-cohort gate, and the deterministic disposition rule. The implementation binding is caller-supplied and closed. It contains bounded project-relative regular-file byte digests plus deterministic registration, start-admission, liveness, worker, construct-probe, completion-predicate, normalizer/grader-function, and schema descriptors. Contract hashes and logical versions are not implementation identity.
- `PairedEvaluationResultV1` contains every scheduled held-out trial, terminal/output refs, measurements, explicit failure accounting, pair coverage, aggregate deltas, named-ablation metrics, deterministic mutation evidence when frozen, optional independent semantic qualification with host-only arm mappings and receipt IDs, policy outcomes, one of `NO_BUILD|RETIRED|CANDIDATE|INVALID_EVALUATION`, and a body-derived result ID. Readiness calibration is deliberately absent from scoring and aggregate result counts. `INVALID_EVALUATION` requires its bounded incompatibility marker and `all_passed:false`.

Unknown fields fail. Real warrant and Part B populations require at least five unrelated domains plus positive and negative trigger tasks. A contamination group declared as development/tuning data fails before trials.

## Freeze and execution

1. Validate population and plan.
2. Canonically digest the population and plan.
3. Resolve the caller-selected direct-agent baseline, candidate, and every ablation. Recompute the caller-supplied implementation binding from actual registrations, grading functions, runtime descriptors, and exact file bytes. Reject missing material roles, absolute/noncanonical/escaping paths, symlinks, non-regular or oversized files, byte drift, function/schema drift, or any descriptor mismatch. Required files cover every registration's guidance and agent definition; baseline registration; candidate/ablation registration, contract, playbook, validator, and composition sources; normalizer/grader sources; and material evaluator, worker, artifact-store, and artifact-preflight sources.
4. Verify the direct baseline definition and the complete grading definition. The generic direct-baseline factory binds registration name, agent, phase, guidance root/resolution, typed output port, and optional liveness; freeze requires its directive, worker phase, guidance, producer, active output port, and `directBaselineDefinition` to agree. The exported direct Demetri baseline is one compatibility instance, not evaluator architecture.
5. Materialize and digest the complete task × repetition × variant schedule from the frozen pair-order seed.
6. Re-check the complete plan, population, schedule, implementation binding, files, functions, schemas, registrations, and grading definition immediately before trial 1 and again on every resume. Any drift refuses before model work or journal reuse.
7. When independent semantic review is configured, verify the exact prepared authorization manifest and a separate operator-owner approval receipt through a caller-supplied host trust verifier. Reconcile the manifest's schedule digest and canonically sorted arm/binding set against the frozen schedule before executor preflight, catalog/model resolution, or any trial/judge client/session. The manifest binds package, execution and judge model/runtime, prompt/schema/implementation digests, roots, egress scope, validity, nonce, ceilings, resume policy, and forbidden actions. No caller boolean or model field is authorization.
8. Run the executor preflight before creating the worker loop or any trial client/session. Local-live binds the explicit evaluator state root into the process, requires host/tool project and artifact-root equality, persists one deterministic sentinel, and verifies its exact complete bytes through the production model-visible `artifact_read` core. Never scan or fall back to another root. A local-live calibration caller passes the same semantic-authorization preflight into model preflight so it runs before catalog/model/provider access.
9. When readiness is frozen, verify its cohort digest, disjointness, exact arm coverage, and state root, then execute it before opening the held-out population. Normalize every readiness product through the same implementation-bound arm normalizer and validate provenance. Any floor, identity, normalization, provenance, or integrity failure refuses before held-out start. Readiness uses calibration-only trial identities and durable runtime artifacts but never enters the held-out result's pairwise grades, means, intervals, harm counts, or promotion counts.
10. Execute baseline and candidate through their exact generic registrations, `OrchestrationService`, engine, worker, liveness controller, artifact store, and registered guidance. A subset-absent phase activates its agent YAML exactly, including ordinary candidate registrations used directly as evaluation aliases. Evaluation-only direct baselines or ablations may retain a canonical-registration-bound strict YAML subset, with the subset included in the registration digest and worker invocation metadata and validated before session creation. A direct baseline receives only its operational task identity, goal, recursively oracle-free closed task constraints, exact input refs, frozen model binding, and non-oracle schedule identity. Its start constraints, directive task, invocation, session opening, worker artifact, and recoverable pending directive must never contain grader case IDs, trigger truth, expected answers/outcomes, protected flags, evaluation thresholds, mutation oracles, grader descriptors, or tool-selection data. All grading definitions, readiness/mutation oracles, trigger labels, protected-capability labels, mutation data, policy thresholds, and registration tool subsets stay host-owned. Candidates and ablations continue to receive the population task's actual goal and constraints at start admission.
11. Resolve the terminal product from the active registration's terminal `output_artifact_ref` and output port, re-read those exact bytes, normalize through the selected registration's normalizer, and pass only the common wire bytes to the deterministic grader. Exact decision-request lineage is a declared metadata role: required routes accept exactly one direct request ref, reject duplicate/foreign refs, verify its schema/producer/run/branch identity, and require the sealed Decision to name that exact artifact. Direct decision-report parsing admits ordinary Markdown blank lines around required headings while retaining strict field order and exact JSON parsing.
12. When a caller selects resumable execution, persist and exact-byte re-read one immutable `penny.evaluation-trial-observation.v1` artifact immediately after each explicit terminal. A resumed run skips only exact schedule-bound journal entries; an absent entry remains pending. Unknown host/process exceptions abort without minting a terminal observation.
13. Execute pending entries with caller-bounded concurrency from 1 through 4, preserving frozen ordinal result order and counting every terminal failure.
14. For every successfully normalized scheduled arm, construct the blinded packet only from module-issued, task-specific Decide V3 or Plan V2 projections validated against closed request, wire, expectation, and attestation schemas. Generic callers cannot pass packet JSON. Trial and Q4 use distinct closed packet/output schemas; the Q4 packet has fixed derivation and contamination attestations and no candidate semantic wire. Recursively reject normalized snake/camel/mixed/separator/confusable forms of arm, trial, provider, model, performance, run, receipt, artifact, transport, provenance, candidate-output, and related metadata at every packet placement. The private judge session loads no tools except the typed terminating `submit_semantic_review` tool and forbids prose fallback. After authorization, resolve the catalog judge model and admit the exact provider, model, and credential-free allowlisted egress origin before creating any session or reaching transport; never accept a caller-supplied production `ModelClient` or model-client factory. Any test transport seam must remain below these controls. Task-specific Decide V3 or Plan V2 merge logic remains authoritative: structural `FAIL` dominates, every applicable clause must `PASS`, and `UNVERIFIABLE` blocks.
15. Persist the semantic qualification in the result artifact. A deterministic-only harness remains runnable but records `NOT_QUALIFIED / SEMANTIC_REVIEW_NOT_CONFIGURED` with zero semantic provider calls. Configured qualification requires every scheduled baseline, candidate, and ablation arm/repetition to be reviewed and qualified; host arm mappings never enter the judge packet.
16. Persist exactly one version-1 `evaluation-result` artifact with content schema `penny.paired-evaluation-result.v1`, then re-read its manifest, bytes, and closed contract.

The default gate uses a deterministic offline model fixture, a frozen known-delta implementation binding, and temporary owner state. The fixture scripts responses by task identity and does not read grader IDs, trigger truth, grader descriptors, or oracle values from the model-visible baseline surface. Source guards plus runtime probes use distinctive marker values to verify the direct-baseline start constraints, invocation task, session opening, durable session/output artifacts, and recoverable state remain oracle-free. Local-live evaluation is a separate caller-composed path: it requires both an explicit CLI opt-in and `PENNY_EVALUATION_LOCAL_LIVE=1`, an explicit absolute `PENNY_STATE_ROOT`, an exact pre-trial Node/Penny runtime check, an exact resolved provider/model/thinking/rate-card check, a credential-free HTTP loopback model URL, and caller-supplied candidate, ablation, population, grader, mutation, state, and evidence paths. The dedicated factory process-binds that root before Pi client/session resource creation and reasserts the cached binding before every trial; a conflicting process root fails without mutation. The zero-rate local-live client overrides every variant uniformly and denies a resolved-model mismatch before session creation. No local-live helper grants admission, promotion, enablement, package movement, or production registration.

## Failure and policy rules

Missing, nonterminal, cancelled, malformed, and errored trials remain in the result and receive the plan's frozen failure measurement. They are never dropped from means, costs, latency, trigger/protected projections, or pair coverage. Explicit model/liveness outcomes carry a closed diagnostic code; unknown host/process exceptions abort and leave their journal absent. Run accounting separately reports newly started trials, newly recorded terminals, retained journal observations, outstanding schedule entries, and loopback provider calls. A normalizer's explicit `invalid_output` response is model-output failure and remains an ordinary malformed trial.

Missing/mismatched registrations or normalizers, semantic-authorization failure, malformed/foreign/digest-mismatched semantic evidence, judge output/parser failure, unresolved unknown provider completion, artifact-read preflight failure, a thrown/incompatible normalizer, or a grader/parser rejection after successful normalization is evaluation-infrastructure incompatibility. Persist `INVALID_EVALUATION` with a bounded stage/code/trial marker, retain produced output refs, set `all_passed:false`, and do not convert infrastructure failure into candidate-quality failure. In particular, a Part B parser incompatibility is not `RETIRED`.

Independent-review progress is an immutable artifact journal with exactly `prepared → invoking → raw_output_recorded → validated → completed`. Identity binds authorization and approval digests, package, execution/judge models, task input, semantic wire when present, oracle projection, prompt, packet/output schemas, implementation, and packet. Exact completed work resumes with zero provider calls; retained raw output resumes at validation; `invoking` without raw output refuses automatic reinvocation. Artifact metadata parent refs and record parent digests are both reconciled. The host invocation receipt binds raw and validated output digests and is never model-authored.

A frozen readiness failure is reported at the `readiness_preflight` incompatibility stage with `READINESS_PREFLIGHT_FAILED` and refuses before held-out start. Readiness observations are never retroactively inserted into a historical result. Provider-free safe-recovery replay is diagnostic evidence only: it may project how frozen historical bytes would normalize under the repaired implementation, but it cannot rewrite or reclassify the observed historical result.

`CANDIDATE` requires complete pairing, material primary uplift, the protected-capability floor, trigger precision, the negative-transfer ceiling, cost/latency ceilings, every frozen named-ablation floor, and the deterministic mutation gate when present. Mutation measurements must exercise the same registered trial, terminal-product, completion, and composition paths that protect real products; direct schema/seal/summary helper calls alone are not E2E evidence. When a mutation targets a host-only product field, a draft-only ablation records it as not applicable and excludes it from that ablation's applicable denominator and escape count, while the full-product cohort denominator remains frozen. An ordinary candidate failure produces the plan's frozen `NO_BUILD` or `RETIRED`; `INVALID_EVALUATION` is non-dispositive for quality. The result schema has no admitted state, approval receipt, promotion authority, registry mutation, package move, or enablement operation.

## Local benchmark gate

```bash
make evals
```

This optional command requires caller-supplied files under the ignored `$PROJECT_ROOT/evals/` directory. It runs the local synthetic known-delta plan and Plan provider-free control. These benchmark runs have no admission, promotion, enablement, or production-registration authority.
