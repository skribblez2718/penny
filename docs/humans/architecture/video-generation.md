# Video generation: executable core, production unqualified

Penny has a registered story-to-video workflow, hidden from model discovery and available
by exact-name `skill` invocation with explicit private host configuration. Its TypeScript
executor covers story and script, five human gates, references and voice, moving drafts,
master review, native packaging and local delivery. This is implemented control flow,
not a claim that a deployment can produce a finished film and editing package.

The foundation checks requests, finite budgets, current rights and exact dependency
versions. It separates preview permission from draft and final permission, preserves
human approval waits through restart, and validates rational timing and route-specific
inputs. Changing an input removes affected approvals and reviews without discarding
unrelated passing work. A clarification answer never authorizes compute.

These checks depend on privately supplied host bindings. A readable license file is
not proof of clearance, a qualification fixture is not a tested deployment, and a
synthetic audio fixture is not intelligible speech. Models cannot choose backend
addresses, executable graphs, filesystem destinations or rights authority.

## Audio sources: checked references, not proven speech

New read-only audio checks bind captured media, decoded-measurement fields and receipt
references to current rights and consent. They reject unsupported generators and
conservatively prevent double-playing speech from a source clip and a separate stem.
They do not generate, decode, strip, mix or play audio. Production admission still requires actual decoding, timing and playback proof from the
separate fixed host adapters; silent test audio cannot prove intelligibility.

## Shared capacity: opt-in runtime checks, no production activation

An opt-in capacity core now reserves all required resource and budget allowances in one
transaction. It protects finishing allowances, accounts for measured spending once, and
keeps uncertain remote work reserved through restart. Tests use separate processes and
real temporary databases; they do not prove the deployed GPU layout or control external jobs.

The generic host runtime can now enforce these reservations when the host explicitly
opts in. It checks capacity before adapter entry and submission, rechecks exact demand
on restart and replay, and requires final measured usage plus proof that remote work
ended before releasing unused allowances. Missing measurements block result consumption;
uncertain work stays quarantined. Independent inactivity and optional elapsed limits
cannot be extended by transport polls or lease heartbeats, and cancellation observation
uses a bounded cleanup grace.

New queued runtime reservations can park without occupying their backend and reacquire
only after current authority, demand and a fresh fence are verified. A trusted host source
can renew productive pre-fetch work from exact immutable evidence, never adapter-supplied
counters. Original queue limits and independent elapsed/cost/cleanup caps still apply.
Legacy V1 records are not silently converted to the new V2 semantics. Production measurements,
physical-resource bindings and external-job exclusion remain unqualified. Existing
adapters retain their original lease keys, startup does not install capacity policy,
and a reservation is never permission to generate.

The global catalog schema is now version 4. Retained version-2/3 catalogs need an
explicit, verified backup-first upgrade before a deployment uses this version of the
runtime. Ordinary startup does not perform that upgrade. No retained state was upgraded
by the capacity tests.

## Current approval and crash recovery

Image-reference authority now reloads current approvals, selected versions and rights from the
actual run checkpoint. Copying an older approval list cannot restore revoked permission. Fresh,
whole-image, mask and rectangle paths recheck that authority around asynchronous work and native
child import; a cancelled parent cannot spend its former scope.

The retained video/upload adapters can explicitly opt into paired request/intent records and
later receipt-citing result wrappers. Real-owner local fixtures verify recovery without a second
remote POST. A decode-adapter fixture likewise recovers its later result without re-decoding;
its subprocess output is simulated, not a qualified decoder installation. The registered video workflow consumes these boundaries, but the additions alone grant no
approval and prove no playback, speech or native-project quality.

## Private configuration and honest completion

The intended result is both an audible, fully decoded and reviewed master **and** a
portable native Kdenlive project with original assets. Structural MP4 checks, still
boards, generic editing interchange files and proxy-only packages cannot establish
that result.

Seven fixed completion checks are wired to current approvals, final shots, audio/playback,
portable native projects, rights, exact delivery and settled effects. They inspect exact
artifacts and owner journals rather than accepting caller PASS flags. Missing or unqualified
evidence still blocks success; a native result marked `constructed_unqualified` cannot pass.

The default skill extension can load an explicitly selected private JSON manifest. A complete
minimal offline fixture reaches the first human gate and reopens it through the real skill
tool, without injected providers. It intentionally has no effects: it is not a film-production
configuration. Private paths, service identities, profiles, policies and model pins remain the
operator's inputs, not public defaults. Startup neither installs policy nor starts services.

The native voice observer can inspect pinned process, file and GPU facts. Missing loaded-model
or exclusive-admission evidence remains not-ready; health and available GPUs are insufficient.
A separately pinned native/CPU test now drives the default private JSON composition
through all five gates, real decoding and editor rendering, exact frame/PCM comparison,
portable packaging and local delivery. It closes and reopens both SQLite owners at
native/delivery crash boundaries and checks replay without recopy. This is real local
native and filesystem evidence with synthetic content, scripted reviews and a simulated
generation backend—not a production film qualification.

Production metering, audible performance, production legal clearance and all 18 route
productions remain unqualified. Passing local tests neither activates a production
provider nor authorizes external publication.

## Managed backend source integration

The default private video configuration can bind Comfy through its managed private
relay. Penny closes every overlapping registered service before native GPU observation,
then binds one exact approved graph to the guarded operation. Actual socket counters and
confirmed backend drain are required before final settlement. Missing observation,
ambiguous acceptance or incomplete accounting keeps capacity blocked.

Required nested Comfy inputs, including literal dotted keys, are validated against the
installed node contracts rather than omitted or silently defaulted. Legacy HTTP render submission
requires explicit opt-in and does not prove managed exclusion. Reference upload still uses
the bounded multipart HTTP client, even with managed preparation and metering. Managed
render submission uses private IPC; its HTTP calls are read-only. Legacy HTTP interrupts
remain disabled without current deployment custody: only exact terminal observation or
quarantine is available. A cancellation acknowledgement or terminal history alone cannot
replace managed job/device/socket drain or final measured accounting. Provider-free tests exercise
real local IPC, journals and socket counters with fake compute. Installation, cross-user
process observation and real GPU behavior remain separate deployment qualifications.

## Bounded cold Voice preparation

The fixed operator CLI now has a separate `prep --requestfile=PATH` management
entrypoint. Its closed request captures the explicit preparation brief and exact
bindings in the existing project journal; it grants no narration, G1, rights or
film authority. Registration uses no model workers or new generic skill.

The existing host owner reserves shared capacity and a backend fence before
external-service closure, cold identity/drain inspection and native baseline.
Only the durable submission guard opens the owned preload command. Cold
inspection does not require already-loaded models. Successful preparation does
require the actual verified engine/model/device observations, same-epoch drain,
transfer counters and final native measurements. A partial load, uncertain drain
or guarded crash quarantines the original hold instead of retrying preload.
Ordinary film/narration readiness remains strict.

Source/runtime/model manifests and all resource paths remain private caller
inputs. Large fixed runtime import inventories use bounded canonical bindings,
not a widened provider-message parser. The synchronous preload window must fit
inside the observed service control lease. Operator activation and independent
CPU/network controls remain prerequisites; neither this CLI nor configuration
checking starts/restarts services, installs policy or enables a film manifest.
Offline tests cover protocol behavior and actual fake-engine IPC loading, not
real GPU residency or production qualification.

## Human playback in Pi

At an existing final-playback wait, the registered skill tool can request the
actual file and playback-device details through the interactive questionnaire.
Its native completion supplies a private read-only viewer URL and a one-time
questionnaire for the actual viewer's response. The running Pi owner retains the
submission callback; no shell subprocess can sign for it.

Only an entirely positive, complete sound-and-picture attestation records playback.
Negative or cancelled input keeps the film blocked. This records what the user
attested, not authenticated watch proof. The original engine clarification and G5
approval remain separate decisions. Tests use synthetic media and UI input; no
production viewing is established. See the
[operator procedure](../../../apps/orchestration/VIDEOGEN-HUMAN-REVIEW.md).

## Normal trusted-local APIs

An explicit API mode now uses the existing local Voice and Comfy HTTP services without
Penny service patches, privileged process inspection, restarts or all-model preload.
Voice captures the selected saved voice, exact text/narration/job, original responses and
actual WAV/PCM output. Current approvals, rights, budgets, capacity and immutable result
custody remain required. It does not claim which voice the engine actually resolved,
whether it fell back, per-chunk execution, or exclusion of unrelated/manual jobs.

Its meter charges allocated CPU/GPU slot time, actual bidirectional socket bytes and
known owned cache/artifact/delivery payload lengths at configured internal tariffs.
Those are not kernel usage, internet-egress billing, total disk usage or money.
Unfinished counters and ambiguous jobs still block settlement; cooperative cancellation
is not physical drain proof. This is a deliberately weaker, separately labeled assurance
than managed native observation, not a way to satisfy missing playback or film quality.

The fixed CLI exports JSON schemas and a read-only Voice binding builder. Startup still
cannot install a policy. An explicit policy-version command can preserve and replace the
selected policy only in a catalog with no admissions, without changing quotas, reserves
or unrelated bindings. Deployment-specific files remain private. See the
[operator procedure](../../../.pi/skills/videogen/resources/private-runtime.md#normal-trusted-local-apis-no-service-instrumentation).

## Preparing actual API outputs for editing

The runtime can keep a backend's original video while creating a separate canonical
editing copy, with an explicit lossy-conversion record. Newly generated narration can
receive a zero-only tail to match a declared scene endpoint; it cannot be silently
trimmed or resampled. A bounded one-shot composition uses current measured narration
and accepted picture, rather than old test media or a prebuilt edit.

Host-supplied story and script choices do not replace reviewers or create approval
receipts. The five gates, independent final playback, current legal clearance and
seven completion checks still apply. A complete configuration is not a completed film.
