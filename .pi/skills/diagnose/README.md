# Diagnose candidate

`diagnose` is a source-defined, registered universal orchestration workflow. It is model-visible through native discovery and Penny's model-facing catalog; explicit `skill` invocation is routed through the sole executable playbook registry and its bound contract. Model visibility grants no authority to bypass host consequence boundaries.

```text
intake → Annie causal decomposition → Ida competing hypotheses
       → Demetri adjudication + proposed non-executed checks
       → host canonical seal → Vera validity verification
       → host validity receipt + integrity/envelope admission → complete
```

Host seal rejection creates a readable `SealDiagnosticV1` for the exact rejected draft, including the final rejection. Seal corrections follow actual operator policy, with no invented finite allowance when unspecified. Each rejected draft gets its own exact diagnostic before another attempt or honest negative terminal; previous-epoch diagnostics are not current instructions. Old diagnostics never enter a new epoch. Seal corrections do not spend semantic review repair budget. An exhausted run is incomplete; its rejected draft is not a canonical product.

## Frozen boundaries

- Analysis only: no test execution, probe execution, external retrieval, remediation, taskification, mutation, or approval.
- Ordinary workflow phases omit `allowed_tools`, so runtime activates each assigned catalog agent's exact YAML tool list. `artifact_read` is mandatory for exact predecessors and no other channel may replace a missing ref. Other YAML tools are usable only when materially relevant and allowed by caller/task and this analysis-only boundary. Ordinary permitted work has no invented model-turn, phase-admission, tool-call, external-call, or total elapsed-work quota; actual operator limits still apply; calibrated renewable inactivity leases stop stalled workers, host operations use independent renewable inactivity leases, and routing-only repair remains separate, governed by actual operator policy and measured-error/inactivity controls, and neither grants external-acquisition, remediation, execution, or mutation authority.
- Annie decomposes causes; Ida forms competing hypotheses; Demetri ranks and adjudicates; the host seals; Vera verifies validity; the host alone mints receipts and admits completion.
- Vera `analysis_gap` and `evidence_gap` return through Annie, Ida, and Demetri. `diagnosis_product_gap` returns to Demetri. Every revision is resealed and reverified.
- There is no Carren phase.
- The host derives canonical `DiagnosisV1` with exact request/decomposition/hypotheses/draft lineage and literal `tests_executed:false` and `remediation_started:false`.
- Pre-review native host checks are bound into the signed verifier task as canonical `HOST_MECHANICAL_CHECKS`; they establish mechanical validity, not semantic approval or effect absence. Post-review receipts/envelopes are not verifier prerequisites.
- Vera `UNVERIFIABLE/verification_incomplete/none` ends durably incomplete with findings and evidence limitations, no author repair or positive receipt. A valid inconclusive product remains eligible for PASS; unknown effects alone are not a defect.
- Review routing repair preserves the complete original SUMMARY judgment and confidence. A missing judgment cannot acquire PASS. Exact request/candidate/failure recurrence can end `repair_stalled` on product gaps only while upstream decomposition and hypothesis bytes remain unchanged throughout the run. Analysis/evidence gaps and any changed upstream prose are unmeasured (`null`), not proof of progress. No time/count cap or prose classifier is added.
- A current-product Vera PASS is necessary but not sufficient: deterministic integrity and envelope artifacts must bind the exact accepted execution evidence before completion.
- Valid `inconclusive` and `not_applicable` outcomes may complete. Missing exact material or exhausted repair is non-positive `incomplete`.
