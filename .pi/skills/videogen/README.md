# Videogen executor

The hidden exact-name skill is registered and executable with explicit private host configuration. Without explicit private configuration, the default runtime refuses before run creation; this change does not activate a deployment, install profiles or qualify media/editor interoperability.

A real service/engine/runner fixture reaches G1–G5 and publishes both synthetic products through the filesystem delivery owner. Synthetic decoding, playback and native-editor attestations are explicitly isolated fixtures, not live qualification.

## Native Pi invocation

```text
/skill:videogen <description>
```

Pi loads the manifest through normal native discovery. No additional resource hook, `--skill`
flag or custom slash router is required. Run `/reload` after package changes in an existing
session. `disable-model-invocation: true` keeps videogen absent from automatic model
advertising while preserving this manual command. The skill extension supplies its registered
execution entrypoint, not a separate visibility mechanism.

Native expansion gives the parent model the manifest plus description. The parent must call
`skill` with `skill_name: "videogen"`, `goal === request.brief`, and the complete closed request
in `constraints`; missing information needs clarification. Neither expansion nor model dispatch
supplies private activation, changes limits or approves a gate. See [SKILL.md](SKILL.md).

## Runtime and boundaries

The fixed executor lives in `$PROJECT_ROOT/apps/orchestration/src/playbooks/videogen.ts`; private configuration, deterministic stage materialization, current-gate effect checks, seven completion proofs and 18-route evidence status live under `$PROJECT_ROOT/apps/orchestration/src/videogen/`. Providers supply registered operation declarations, request schemas and constructor-bound adapters—not arbitrary phase evaluators or completion callbacks.

A private host supplies `VideogenRuntimeProvidersV1`. The skill extension's `createSkillExtension({ videogen })` factory and `OrchestrationService({ projectRoot, playbookName: "videogen", videogen })` use those same bindings. The default extension also accepts the explicit `PENNY_VIDEOGEN_RUNTIME_MANIFEST_FILE` private JSON binding; see [private-runtime.md](resources/private-runtime.md). Recovery checks the exact configuration fingerprint. No environment path guessing, model-selected module loading or retained-state installation occurs.

Controlled imagegen has a separate serial, digest-bound child policy and native request binding. The ordinary seven-child authority is unchanged. Optional informational children use a separate parent-only authority and return exact results to their original worker. Objective contradictions route through bounded synthesis and a fresh verifier pass. Independent human AV playback has a trusted exact-ref capture API and a checkpointed clarification wait. Current native raw outputs that remain `constructed_unqualified` cannot satisfy positive completion; usable production requires qualified concrete providers, including independently qualified timeline/master rendering. A fixed bounded timeline renderer is available, but its existence is not AV or native qualification.

## Verification and qualification

The native-command E2E submits literal `/skill:videogen <description>` to a real parent
`AgentSession.prompt`, uses a scripted in-memory faux provider to emit the normal registered
tool call, and reaches durable real-engine G1 without effects or approvals. Worker cognition
is fixture-backed, as is parent cognition; the parent prompt/tool loop, native expansion, admission
and engine remain real. It checks private-manifest refusal and same-run G1 reopen without redispatch.
This is **command-path conformance**, not live-model, completed-film or all-route qualification.

Provider-free checks establish contracts plus executor/control-flow and isolated publication behavior. They cannot establish a deployed profile, actual voice, native interoperability, legal clearance or production quality. No live model/service/editor operation is run by these package checks. Manual production and all 18 distinct route productions remain unproved.
