# Plan contract reference

## Request and exact composition

`PlanInvocationV2` is the closed caller wrapper around `PlanRequestConstraintsV1`, with an explicit `specification_assurance` choice (`reviewed_definition` or `semantic_only`). Legacy V1 constraints map only to `semantic_only`. A request without a SpecificationV1 input records `not_applicable`; strict mode with a supplied specification requires a completed Define producer and its exact review graph before a run is created. Assurance binds provenance to reviewers, integrity, the envelope, and final admission; it never changes the SpecificationV1 semantic input.

`PlanRequestConstraintsV1` is the closed native request shape: desired outcomes; provided current-state facts or an unavailable reason; hard constraints; non-goals; material uncertainties; and prior decisions. Canonically equal duplicates fail. The host combines the admitted goal and sorted exact input IDs, then derives `request_id` from the complete request seed.

Typed semantic input ports admit at most one exact `SpecificationV1`, `GroundedSynthesisV1`, `DecisionV2`, and `EvidenceContextV1`. Plan has no caller-composed prior Strategy input. Admission checks the canonical manifest ref, kind, schema identity/version, registered validator, and exact bytes before run creation. Transport envelopes cannot substitute for semantic products.

Piper orientation precedes one host `EvidenceAdmissionV1` bound to the exact accepted routing result. Only a typed strategy-blocking gap opens bounded Echo; otherwise the host routes directly to strategy authorship. When caller constraints permit, Echo may acquire narrowly targeted read-only local or web evidence only for that exact gap, must preserve source locators, and must report unresolved evidence honestly rather than broadening into open-ended research.

## Exact specification source index

Before worker dispatch, the host derives and persists one canonical `PlanSpecificationSourceIndexV1` artifact from the selected exact canonical SpecificationV1 bytes. It binds the full specification ref and SHA-256 and contains every source row, ordered exactly as the existing trace validators expect: requirements, constraints, non-goals, assumptions, risks, open questions, and standards, sorted by source item ID then type. Every row retains its zero-based coverage index, exact item ID/type, required flag, JSON-pointer locator into the specification, and canonical source-value SHA-256. Objectives and acceptance criteria remain authoritative semantics but are not coverage-index rows.

Every specification-informed worker and review receives that exact ref in `input_artifacts` slot `plan-specification-source-index` alongside `prior-specification` and must fully read both with `artifact_read` through `next_range`. The full index stays only in the artifact, never in task prose, metadata, or checkpoint context; no rows are summarized or truncated. Missing refs return `missing_input:`. Host dispatch/recovery and completion reproject the index against exact source bytes and refuse missing, corrupt, substituted, or wrong-source artifacts rather than regenerating a weaker namespace. The index is a deterministic transport product, not independent evidence or reviewed-definition assurance; strict assurance, source bytes, and semantic coverage validators are unchanged.

## Draft transport and semantic rules

Piper returns bounded strategy prose followed by one line-start `STRATEGY_CORE:<single-line JSON>` footer and one final SUMMARY. Strict UTF-8, no BOM/NUL/CR, no code fences, no duplicate marker, and no trailing content are enforced. JSON key order, legal insignificant whitespace, and ordering of set-valued arrays do not affect validity. Exact prose bytes are preserved.

The active V2 model core contains disposition, applicability reason, indexed outcomes, indexed dependencies, indexed request coverage, blockers, confidence, generic source-item coverage, and unsupported strategy elements with derived-need rationales. It contains no artifact refs, tasks, task graph, execution, approval, action state, or host lineage. When SpecificationV1 is absent, the two source-traceability arrays must be empty.

- Every index is unique within its set field and in range.
- Each outcome links to at least one desired outcome.
- Dependencies have existing distinct endpoints, are unique, and form an acyclic graph.
- `ready` covers every desired outcome and exact request/input context, with no blockers.
- `blocked` has blockers and blocked desired outcomes; linked plus blocked outcomes cover every desired outcome.
- `not_applicable` has no outcomes, dependencies, blockers, blocked outcomes, or coverage claims.
- No edge or executor task is manufactured merely to create a sequence.
- With SpecificationV1, every mandatory requirement, hard constraint, non-goal, blocking question, and binding named standard is covered exactly once as `addressed`, `blocked`, `deferred`, or `not_applicable`; `addressed` entries map to outcomes.
- Every specification-informed strategy outcome maps backward to source items or carries an explicit derived-need rationale. A specification whose planning handoff is not ready cannot yield a ready strategy.
- Request/specification conflicts remain visible. Evidence can resolve facts but cannot silently revise caller intent, normative requirements, or profile semantics.

## Stable host projection and lineage

`stable_id(namespace,value)` is `namespace + "-" + sha256(canonicalJson(value))`. Fixed namespaces cover the request, request-item families, outcomes, and strategy. Request-item IDs hash values rather than positions. Outcome IDs hash projected outcomes without their IDs. `strategy_id` binds the semantic product, request digest, and exact report digest while excluding run-specific artifact IDs.

Set-valued IDs, dependencies, blockers, outcomes, source coverage, and unsupported-element records are canonically sorted in active `StrategyV2`. The product embeds the exact report, complete request and digest, exact request/draft/input lineage and digest, raw draft digest, exact SpecificationV1 source artifact identity when supplied, and `execution_started:false`. `StrategyV1` sealing/validation remains available only for historical explicit compatibility; the active playbook, review subjects, integrity graph, envelope, and completion predicate bind V2. Neither strategy version is a caller-composition port.

Seal corrections follow actual operator policy, with no invented finite allowance when unspecified. Each rejected draft gets its own exact diagnostic before another attempt or honest negative terminal; previous-epoch diagnostics are not current instructions. The host persists an exact `SealDiagnosticV1` for every rejected draft, including a final rejection on actual policy exhaustion. Only same-run feedback after the last checkpoint-selected sealed product enters the next corrective author invocation. A reviewer-driven replacement starts a new epoch; its product must again pass Vera then Carren with fresh receipts. On seal exhaustion, `seal_diagnostics` names the final diagnostic and rejected draft separately from semantic `repair_diagnostics`; any negative terminal output ref is a **rejected draft**, not an accepted product. Historical seal-feedback artifacts remain readable but never grant new corrections.

## Review receipts and terminal truth

A review subject binds the exact request, distinct Piper orientation, host evidence admission, optional Echo evidence, imported products, Piper draft, latest sealed strategy, product digest, and admitted-upstream digest. Vera PASS produces a host validity receipt only for that subject. Carren receives the exact Vera-passed subject and host validity receipt; Carren APPROVE produces the dependent quality receipt.

Any product revision changes the review subject, invalidates prior receipt substitution, reseals the product, and requires Vera then Carren again. A deterministic integrity artifact and envelope bind the latest product, both reports, both host receipts, and signed worker execution evidence. Completion rejects stale or substituted refs and receipts.

## Recovery and consequence boundary

Host feedback, sealing, receipts, integrity, and envelope persistence are deterministic and idempotent across recovery. Closed evidence, analysis, and product gaps use engine-owned routes under actual operator policy. Exhausted or stalled work is `incomplete` with an exact typed reason and the latest exact partial; cancellation is `cancelled`. Missing exact material is typed `incomplete`, with no internal clarification state. Engine faults remain out-of-band `error` results rather than Plan states.

Planning completion means the planning assessment is complete, not that the underlying goal has been achieved or execution is ready. This is especially explicit for `blocked`. Ordinary workflow phases omit `allowed_tools`, so runtime activates each assigned catalog agent's exact YAML tool list. `artifact_read` is mandatory for every needed exact workflow predecessor and no other channel may substitute for a missing ref. Other YAML tools may be used only when materially relevant, permitted by caller/task, and within the phase consequence boundary; only the host-admitted Echo gap permits targeted local/web evidence acquisition. Ordinary permitted work has no invented model-turn, phase-admission, tool-call, external-call, or total elapsed-work quota; actual operator limits still apply; calibrated renewable inactivity leases stop stalled workers, host operations use independent renewable inactivity leases, and routing-only repair remains separate, governed by actual operator policy and measured-error/inactivity controls. No path executes, mutates, taskifies, introduces Tabitha, enters an approval state/directive/gate, changes executable registration or model discovery.

## Verification uncertainty and repair progress

Vera's closed negative verification outcome is `UNVERIFIABLE/verification_incomplete/none`, with nonempty `findings` and `evidence` describing the limitations. `strategy_delta` remains required but does not authorize author repair. The terminal exposes `verification_findings`, `evidence_limitations`, exact `feedback_report_refs`, and a best partial. It is durable incomplete, not a positive receipt/admission, and never advances to Carren. Valid blocked products still follow ordinary validity and quality review.

Both Vera and Carren opt into `routing_repair_policy:preserve_source_summary_v1`. The complete final SUMMARY is already structured judgment: routing correction preserves every detail and confidence exactly, including ordered arrays. Absent, malformed or schema-invalid original judgment refuses rather than becoming a new review verdict. Review prose is not mined for substitute judgment; no extra core/footer is introduced.

The verifier task alone carries canonical `HOST_MECHANICAL_CHECKS` after exact-ref/digest, native request/draft/product schema, coverage, admitted-evidence binding and lineage validators succeed. It contains schema version 1, exact `product_ref`, `source_refs`, named successful `checks`, the domain-specific draft digest, and scope `host_mechanical_only_not_semantic_or_effect_absence`. The lineage digest is SHA-256 of raw Piper draft bytes; specification coverage, exact source-index projection and selected assurance are independently rechecked. The ordinary signed task hash binds this statement without a new receipt kind. Recovery recomputes it against selected exact operands and requires exactly one complete matching evidence line in the frozen task, wherever contextual enrichment places it. Missing, altered or duplicate evidence refuses without rewriting the task; validator failure is `host_mechanical_validation_failed`, never author repair. Later integrity/envelope artifacts cannot be demanded as missing pre-review author evidence.

The registration's paired `exact_fingerprint_v1` methods hash the parsed semantic draft, current analysis/orientation and gathered evidence, admission classification and evidence requirement, current Vera review for Carren, and failed structured details. The host rechecks exact refs, bytes, digests and accepted execution bindings. Report prose, confidence and semantic SUMMARY details are retained; `strategy_delta`, transport identities, revisions, receipt fields and historical feedback are excluded. Request, imported and contextual inputs are frozen. Unavailable or unparseable measurement returns `null`, not a recurrence claim. The shared engine stores phase-scoped recurrence evidence atomically with accepted results. Identical measured content after repair, even A/B/A or a replacement ref with unchanged content, returns `repair_stalled` without another author dispatch or reviewer repair charge. Changed upstream analysis/evidence may continue despite an unchanged draft and findings. Best partials and current reports survive restart. Changed measurements do not prove semantic improvement; no prose-equivalence heuristic, wall-clock cutoff or finite repair default is added.
