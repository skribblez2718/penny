# Source-composition analysis (`sca`)

The public registered `sca` skill now runs scanner/dependency/semantic-graph preparation through focused selection, falsifiable hypotheses, evidence decisions/gathering, supported dispositions, reconciliation, learning assessment and full report review/independent verification in **one ordinary run**. This replaces the former two-full-source-primary/local-release-gate workflow.

The existing registry, OrchestrationService, engine, agent runner, artifacts and HostOperationRuntimeOwner own execution. No accepted phase products, P03 bootstrap, qualification/login/profile/activation records, manual artifact copying or report-release handshake are ordinary prerequisites. Ordinary SCA analysis and its production-readiness assessment require no KVM access, VM image, guest assets, VM configuration or VM qualification. Docker is the current supported application-test containment path; the optional legacy VM backend is compatibility, not a prerequisite. Historical phase qualification helpers and the separate VM broker executable are not the public runtime path or proof that this replacement passed a live deployment check.

## Caller contract

[SKILL.md](SKILL.md) contains the generated invocation/schema. The caller supplies source root, include/exclude scope, execution mode and `deepseek-flash`. The optional expected source digest is verified when present; otherwise the host computes it. Tool/rule/script/advisory paths and digests are caller-selected, not inferred from the audited tree. Every production phase binds `required_model: SCA_REQUIRED_MODEL` (`ollama/deepseek-v4.1-flash:cloud`). The normal default service installs the model guard; absent or mismatched host disclosure consent denies cloud dispatch, rather than trusting the requested model string. Consent is separate from analysis constraints and covers the FULL serialized transcript, source/evidence/tool outputs, exact destination and caller purpose. Optional cost/call/output limits come only from actual operator policy; none is inferred from a test cohort.

Build both packages with `bun run build:orchestration` and `bun run build:sca-service`. The ordinary fixed sibling-package build entry supplies existing shell-free scanner/process/dependency adapters without depending on workspace-link hoisting; no service daemon or activation ledger is needed. Missing native analyzers/configuration remains explicit INCOMPLETE evidence. Installed Joern frontends/query scripts must implement the exact snapshot-bound file-support/row protocol in [the reference](resources/reference.md); a nonempty CPG file or exit=0 is not complete semantic coverage.

## Outputs and trust

Canonical JSON, Markdown and SARIF derive from one accepted set. The manifest binds their bytes and reviews. Reports preserve confirmed/probable/theoretical/unresolved findings, concrete counterevidence, non-findings, scanner/no-alert selection, coverage limits and learning outcomes. Unscored findings, missing CWE, unsupported code evidence or missing material tools cannot become COMPLETE.

Carren reviews report meaning and quality; Vera independently reads the latest product and separately captured evidence. A report review may accept an honestly incomplete representation without upgrading the assessment to COMPLETE. Actionable defects loop through policy-led repair/re-render/fresh reviews. Exact hashes, schemas, quotations, structural checks and deterministic CVSS scoring complement—but do not mechanically prove—semantic judgment.

No target execution, package installation, source mutation, network/advisory lookup, rule promotion or external publication is implicit. Without separate `advanced` operands, application tests remain NOT RUN and candidates remain deferred/not-feasible/quarantined. Scanner silence is not safety.

## Optional admitted testing and learning

`advanced` accepts four independent arrays: `application_tests`, `learning`, `promotions`, `rescans`. All source bindings must match the captured snapshot. The generated caller schema specifies every required field; no paths or grants are inferred. `static_only` forbids application tests, promotion and rescan.

- Application inputs name an exact external harness, source subset, optional inputs/stdin, expected exit code, bounded resources and independent maxima. Admission captures bytes and mints immutable plan/policy artifacts bound to the **actual** run, project and corpus. Demetri may select only an admitted plan ID, never a host command. The registered `sca.application.v1` operation delegates to the native Docker shared-kernel **CONTAINER** adapter or optional legacy VM adapter. The result records RUN, NOT RUN or UNKNOWN, exit/pass, cleanup and quarantine. Raw receipts and streams remain private; neither VM nor CONTAINER test success is exploitation or isolation attestation.
- Learning inputs independently supply pinned tool/baseline, fixture bytes, expected truth, limits and optional pinned offline-validation dependencies. Skribble proposes inert JSON for a single selected rule ID and learning selector. The registered `sca.validation.v1` operation accepts only this run's confirmed-code reconciliation and exact source/evidence pointers. Model-generated test prose cannot replace caller truth. Missing required test classes, drift, truncation, failures and absent confined execution cannot validate a rule.
- `sca.promotion.v1` requires a separate caller grant naming the exact candidate hash, predecessor release, future namespace, successor revision and authority hash. It consumes the exact saved validation record, creates an immutable successor release and never rewrites the retained baseline or source.
- `sca.rescan.v1` requires its **own** caller grant and exact promoted predecessor. Results remain a new investigation revision; newly observed leads are unconfirmed and keep the report incomplete until investigated. Promotion never implies rescan permission.

Ordinary runs use the existing host owner, journal, cache and leases for these four distinct operations. Restart consumes exact cached results without replay. Unprovable post-submission work remains UNKNOWN/quarantined, not a clean retry or success. Reports and both independent reviews receive a sanitized advanced summary, not harness bytes, private paths, raw streams or independent expected truth.

Trusted embeddings configure `OrchestrationServiceOptions.scaAdvanced`. `PENNY_SCA_ORDINARY_APPLICATION_CONFIG` supplies an absolute host-private JSON file matching the closed `OrdinaryApplicationRuntimeConfigSchema`: Docker settings or optional legacy tagged QEMU/KVM settings. The legacy `PENNY_SCA_ORDINARY_APPLICATION_VM_CONFIG` alias still accepts the original VM config. Supplying both is rejected. Neither backend is configured by default; there is no fallback. Missing application runtime refuses only requested application execution, not ordinary analysis. Explicit invalid or ambiguous host configuration is still rejected at service construction; it is not a requirement to supply VM settings.

Caller application isolation omitted or `vm` retains V1 VM consent/resources. Docker requires **both** explicit `isolation: "container"` and `profile: "docker-local-no-network-v1"`, with `operation_timeout_seconds` instead of `vm_timeout_seconds`. Intake captures exact V2 plan/policy artifacts; VM consent never authorizes Docker. Host settings independently pin an already installed local Docker executable/socket and already local immutable image IDs. No pull/build/install is permitted. Results and review summaries label **CONTAINER**, never VM, and preserve RUN/NOT RUN/UNKNOWN, cleanup and quarantine. Docker shares the host kernel; it is not a VM-level boundary. See [the exact configuration boundary](resources/reference.md#application-runtime).

Normal learning configuration can use the absolute host-only `PENNY_SCA_ORDINARY_OFFLINE_CONFIG` JSON file (see [configuration examples](resources/reference.md#normal-host-configuration)). The installed runner composes the existing descriptor-pinned process harness with a pinned local `strace` socket-denial boundary. It runs trusted source-only analyzers, not target programs; it is **not** a hostile-code filesystem/interpreter sandbox. A trusted embedding can still supply its own independently confined `runOffline` and private `workRoot`. There is no unconfined fallback. Missing configuration is an explicit unsupported result.

`PENNY_SCA_ORDINARY_MODEL_CONFIG` supplies exact host consent for one project/run/source snapshot/purpose and destination. An embedding can instead set `OrchestrationServiceOptions.scaModel: {config, admit?}`; the optional narrower policy sees each complete normalized transcript and exact serialized provider JSON. Policy failure cannot be overridden by the model. The default service installs the real exact `artifact_read` extension from its built helper even when ambient discovery is disabled; its store/environment come from the host, not target contents or model parameters. Native SDK automatic compaction is enabled. Its summary requests use the same pinned-model, disclosure, HTTP-call, output and inactivity guards as ordinary turns. Original source messages are checked before SDK summary serialization truncates or flattens tool results; the complete normalized summary context and actual HTTP payload are checked again. Summary text is continuity, never proof that a worker read its assigned artifact bytes. Custom summary hooks are refused. Retry, cache warming and ambient worker extensions remain disabled on this default SCA client only. Shared compaction policy also applies outside SCA. These controls are engineering boundaries, not provider/native qualification or permission to disclose private corpora.

## Policy-led semantic revision

Derive values from actual operator policy, not test constants or model guesses. Do not infer finite step, agent-call, phase-cycle, semantic-repair or correction-attempt caps when none is supplied. Actual disclosure/cost controls, cancellation, trusted progress/inactivity, measured errors and exact custody remain binding. The model host configuration requires an inactivity lease; its call, repair-session, input-byte and output allowances are optional positive safe integers when supplied. Omission adds no such allowance, while explicit null or invalid values refuse. Semantic/report repairs charge the actual run-wide evaluator policy, not a hidden two-revision allowance.

A rejected known cognitive stage can receive fresh **same-stage drafts** under actual operator policy, without an invented finite allowance. A typed host diagnostic binds the original exact input refs, exact rejected response, failure location and minimized expected IDs/source pointer or allowed ranges. The fresh attempt keeps the registered model and disclosure guard; every schema, quotation, ID and evidence validator runs again. The host never edits quotations, drops candidates or substitutes its own cognitive answer. Stable accepted stages and external operations are not rerun. Exhaustion remains INCOMPLETE with accepted predecessors and private rejected-attempt lineage. Malformed routing still uses its separate routing-only repair; custody/host faults are not model-redraft permission.

- `apps/orchestration/tests/sca-ordinary-advanced.test.ts`: real ordinary ingress/engine/owner/artifacts and native learning validator, with explicitly scripted cognition, VM observations and analyzer responses; distinct grants, private/public separation and cached recovery for all four operations. Not native isolation/provider evidence.
- `apps/orchestration/tests/sca-ordinary-runtime-boundary.test.ts` and `apps/sca-service/tests/ordinary-application-container.test.ts`: VM-free ordinary completion, no-action/missing-runtime truth, ambiguous configuration refusal, Docker dispatch without VM preflight and unchanged legacy consent. - `apps/orchestration/tests/sca-playbook.test.ts`: full flow, focused—not full-corpus—worker inputs, scanner-led and AI-only/no-alert findings, concrete counterevidence, missing tools, repair and exhaustion, exact representations and deterministic scoring.
- `apps/sca-service/tests/ordinary-runtime.test.ts`: real bounded process/scanner/dependency APIs using offline executable fixtures; graph/support accounting, identity drift and explicit tool absence. These are not genuine Semgrep/Joern semantic-accuracy checks.
- `bun run test:sca:critical`: broader deterministic SCA/build/typecheck/ingress/architecture checks. Record actual failures, skips and unrun checks; documenting a command is not claiming it passed.

Removing VM prerequisites does not establish production readiness. Fresh live DeepSeek completion through the independent final review remains unverified here. Native-tool and live-model verification remain separate, explicitly authorized checks. Keep caller-private evidence and progress in the caller's own ledger, not this public repository.
