Gates (HITL) — each can refine its own phase

  • charter_gate, context_gate, threat_gate, triage_gate, verification_gate, report_gate. A gate either advances or loops back to refine (charter_gate → charter, context_gate → context, threat_gate → threat_model, triage_gate → triage). threat_gate / triage_gate can also skip straight ahead (→ targeted_scan / → deep_dive).

Scanner TOOL states + evidence loops

  • baseline_scan, targeted_scan run inline (no agent). deep_dive → targeted_scan loops back for more targeted evidence before verification_gate. verification → reverification is an optional 2nd independent pass; both flow to fix_verification → report_gate → report → complete.

Escalation & resume (dashed)

  • Every agent phase (charter, census, context, architecture, requirements, threat_model, triage, deep_dive, verification, fix_verification, report) escalates to unknown on UNCERTAIN / needs_clarification. Those uniform → unknown edges are collapsed into this note (not drawn per-source).
  • unknown → awaiting_clarification pauses for the user; awaiting_clarification then RESUMES at whichever phase escalated — a fixed set of 11 resume targets (charter, census, context, architecture, requirements, threat_model, triage, deep_dive, verification, fix_verification, report), all drawn.

Abort

  • An abort → error transition exists from EVERY non-final state; those edges are collapsed into this note for legibility and are NOT drawn. Each agent runs the model declared in its own .pi/agents/<name>.md (or an SCA_<AGENT>/SCA_DEFAULT env override); TOOL/gate states run no agent.
