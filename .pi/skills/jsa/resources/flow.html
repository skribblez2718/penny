Validated against orchestration/playbooks/jsa.py (JSAMachine) · runs on the shared orchestration engine. Boxes are FSM states; TOOL states run inline (no agent), agent states dispatch one cognitive-primitive agent. MemPalace is the blackboard; only typed per-state SUMMARYs return to the engine.
Two passes. A deterministic TOOL pipeline (acquire → cve_research → sast_scan → normalize → dedup_within_source → correlate_evidence → agent_review → sast_validate → structure → slice) runs with no agent, then the deep pass: investigate is a bounded PARALLEL per-class annie fan, flowing into collect → merge → verify → [reverify] → poc_capture → report → reflect. intake is the only human gate.

Deterministic pass (TOOL states, no agent)

  • acquire → … → slice run inline via run_tool_state: crawl + download JS (with source-map reconstruction), fingerprint tech / CVEs, semgrep + jsluice (+ optional trufflehog/gitleaks) SAST, normalize + dedup + correlate evidence, local heuristic review + validate, then structure (typed store: PageCard/ModuleCard, dangerous patterns) and slice (per-class FlowCards; seeds the INVESTIGATE wave plan).

INVESTIGATE — bounded PARALLEL per-class fan

  • investigate ⟳ investigate (investigate_wave [batch < total_batches]): one fresh-context annie per candidate vuln class (focused on that class + its assets/references/<class>.md catalog), run in BATCHES of up to max_fan_width agents CONCURRENTLY; route_after re-emits the next batch until every class is covered, then ONE trailing generalist SWEEP batch. Candidate classes are page-informed + signal-gated with a core floor — SAST/SLICE hits ∪ dangerous patterns ∪ page signals ∪ dependency-exploitation classes ∪ a client-side floor — so SAST-blind classes still get an agent.
  • investigate → collect (investigate_done [batches complete]).

Evidence-gated verify tail

  • verify → poc_capture (dual_verify off) or verify → reverify → poc_capture (dual_verify on + PASS): a SECOND independent vera (constraints.reverify_model) — only findings both passes confirm are reported verified.
  • poc_capture (TOOL): independently checks for a decodable browser-PoC screenshot per claimed-verified finding and DEMOTES any lacking one to unconfirmed — engine-owned evidence the agent cannot fabricate.
  • reflect → complete (met=True): carren writes learned semgrep rules + FP/FN corrections.

Escalation & abort

  • Escalation (dashed): agent states {investigate, merge, verify, reverify, report, reflect} escalate to unknown on UNCERTAIN / needs_clarification; unknown → awaiting_clarification → investigate (fixed resume target) pauses for the user, then resumes.
  • Abort: an abort → error transition exists from EVERY non-final state (intake, acquire, cve_research, sast_scan, normalize, dedup_within_source, correlate_evidence, agent_review, sast_validate, structure, slice, investigate, collect, merge, verify, reverify, poc_capture, report, reflect, unknown, awaiting_clarification). Those edges are collapsed into this note for legibility and are NOT drawn.
  • Each agent runs the model declared in its own .pi/agents/<name>.md (or a JSA_<AGENT>/JSA_DEFAULT env override); TOOL states run no agent.
