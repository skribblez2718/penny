Mode is data, and it buys a BUDGET — it does not wire the graph: caller constraints.mode wins; otherwise piper declares it in its plan SUMMARY (no keyword detection). The mode expands into critique_passes + max_research_rounds, and the critique detours fire on the BUDGET, not the label — ≥1 buys the report critique, ≥2 adds the plan critique. A standard run given critique_passes: 1 therefore gets an adversarial report read, and opt-in rigor escalation can earn one mid-run. Presets: quick 0/2 · standard 0/2 · deep 2/3. Breadth (max_sub_queries) is deliberately NOT a mode value — mode governs verification spend, never decomposition.

Bounded revise loops & honest exit

  • critiquing_plan ⇄ planning (critique_passes ≥ 2), critiquing_report ⇄ synthesizing (≥ 1) and validating ⇄ synthesizing (every mode) each loop on NEEDS_REVISION/FAIL, bounded by max_iterations. Budget spent → the "exhausted" edge proceeds forward with a warning recorded and the unresolved issues surfaced (never a faked pass).
  • validating (vera) is the evidence-based citation-grounding gate in every mode — the report is written only after claims are grounded, or the budget is spent and the survivors are reported as unverified.

Evidence-seeking — the iterative research loop

  • validating → researching fires when vera FAILS a claim and names evidence_needed and a research round remains (max_research_rounds, default 2 / deep 3; set 1 to disable). The gate's answer to "this claim has no support" becomes go find out, not merely delete the claim — which matters because synthia has no web tools, so re-grounding alone can only ever make the report thinner.
  • The verifier names what is missing; it does not supply it. vera diagnoses the gap, echo (read-only, full search toolset) fills it, synthia integrates, vera re-checks. A verifier that sourced its own evidence would be grading material it authored.
  • Researchers are told that "no supporting source found" is a useful result — without that, dispatching an agent to find support for a claim is an incentive to manufacture it.

Fan-out & escalation

  • researching (echo) fans out one branch per planned sub-query (dynamic_branches, bounded by max_fan_width); only the explicit-quick fast path stays a single echo agent. Fan-in aggregates by weakest branch confidence.
  • Any working phase escalates to unknown on UNCERTAIN, a false *_complete flag, needs_clarification, or a stalled loop. Resume is producer-oriented: → planning (from planning / critiquing_plan), → researching (from researching — the plan is kept), → synthesizing (from synthesizing / critiquing_report / validating).
  • Abort: every working phase can abort → error (arrows omitted for legibility).
